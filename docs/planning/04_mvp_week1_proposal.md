# 今週の MVP 提案（縦切り版）

目標: 「現実の潮位で水位が動く葛西風の干潟を歩き、マハゼを見つけて観察・採集し、図鑑に登録して水槽で眺める」が一周できる状態を、身内テスト用に URL で配る。

## 入れるもの

- 土台: Vite + TypeScript + three 0.186 + Preact。GitHub Pages へ配布。
- 干潟 1 面: 手続き生成の小地形（泥と砂の底質）、潮位連動の水位（東京の調和定数から計算）、昼夜（時刻連動の太陽）。水面は平面 + 法線 + 透明度の簡易版。
- プレイヤー: 一人称、歩く・走る・しゃがむ、長靴の水深制限。
- 生物: データ駆動スポーン（JSON）。マハゼは 3 段階表示。チゴガニは簡易モデルで歩行と巣穴出入りのみ。
- 観察モード: ロックオン、周回カメラ、マクロ、0.25〜2 倍速。
- 採集: 手網のみ、タイミング式。観察ケースに保管。
- 図鑑: 種登録、個体情報、行動記録の枠（マハゼのあくび・ダッシュ）。
- 水槽ビュー: マハゼビューアの水槽環境を流用し、採集した 1 匹をヒーロー表示。
- セーブ: IndexedDB、自動保存、1 スロット。
- 潮時チケット: 無制限、前後 3 日の任意時刻、30 分、ポーズ中停止。
- 日本語 UI 最小限。

## 入れないもの（データ定義と図鑑枠だけ用意）

サッパ・シラタエビ・アサリ・ユビナガホンヤドカリ・シロチドリの実モデル、写真の保存と評価、本格水面、水槽カスタマイズ、ショップ、研究ポイントの消費先、天候、鳥の飛行、サーバー機能、ゲームパッド。

## 日程案（4 日）

1. 圧縮仕様 4 本を提出して確認。雛形、マハゼブランチ統合、地形、潮位、移動。
2. スポーン、マハゼ 3 段階表示、観察モード。
3. 採集、図鑑、水槽ビュー、セーブ、チケット。
4. 調整、配布、テスト手順書。

## リスク

- ヒーローシェーダーを干潟の描画パイプラインへ統合する部分が最大の技術リスク。詰まった場合は今週は標準 PBR 表示で配り、ヒーロー表示を来週に回す。
- 調和定数の入手が遅れた場合は仮の定数で動かし、後で差し替える。
- 19 MB の GLB は初回読み込みに時間がかかる。読み込み画面と進捗表示を入れる。
