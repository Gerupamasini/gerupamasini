# Steam・スマホ版リリースに向けた障害の洗い出し（9 回目）

調査日: 2026-10-11 ／ 対象: `main` の 7cae57a（v0.24.0）

今の Web 版（Three.js + Preact、GitHub Pages）を **Steam（Windows / Steam Deck）** と **スマホアプリ**として出すときに、直す必要があるものをまとめた。エンジンを変えるかどうかの判断は [10_engine_decision.md](10_engine_decision.md)。

重さの区分:
- **必須**: これが残っていると審査に通らない、または製品として出せない
- **重要**: 出すことはできるが、評価や操作感をはっきり損なう
- **軽微**: 余裕があれば直す

「エンジン移行後も残るか」の列は、UE5 や Unity に移った場合にその作業（または決めごと）が無駄にならないかを示す。

## 0. まとめ

| 区分 | 項目 |
|---|---|
| 必須 | ゲームパッド非対応 ／ 水槽・ショップの選択がマウスでしかできない ／ Steam Deck がタッチ端末と判定される ／ 音が一切ない ／ フォントを CDN から読んでいる ／ 英語版を出すなら文言がハードコード |
| 重要 | セーブの保存先がブラウザーのオリジン依存 ／ 終了時にセーブが書き切れない恐れ ／ 更新確認（`version.json`）がパッケージ版で意味を持たない ／ デバッグパネルで時刻を変えられる ／ 日本時間固定で海外のプレイヤーは夜しか遊べない ／ 文字が小さく UI の拡大がない ／ ネイティブのファイル保存と確認ダイアログ ／ 全画面・FOV の設定がない ／ GLB が 276 MB で無圧縮 ／ 実機での性能を測っていない |
| よい土台 | 入力が操作名（Action）の表で一元化されている ／ セーブは 1 つの JSON で、検証・バックアップ・復旧まである ／ 潮汐は同梱の調和定数から端末内で計算しており、通信は不要 ／ 文言表（`ja.json`）と `t()` がある ／ 種データに英名・学名がある ／ 画質プリセットが細かい |

## 1. 入力・操作

| # | 内容 | 場所 | 区分 | 移行後も残るか |

| 1-1 | **Gamepad API を使っていない**。Steam Deck 認証（Verified）はコントローラーで全部遊べることが条件。Steam Input のキーボード割り当てだけでは、カーソル操作の画面で詰まる | `src` に `getGamepads` が 0 件 | 必須 | 操作設計は残る |
| 1-2 | **水槽の生体選択・ショップの道具選択がキャンバスのクリック（レイキャスト）だけ**。キーやパッドで選ぶ手段がない | `App.ts:142-177`、`TankScene.ts:862`、`ShopScene.ts:94`、`ToolShelf.ts:201` | 必須 | 操作設計は残る |
| 1-3 | **タッチ端末の判定が `any-pointer: coarse` または `maxTouchPoints > 0`**。Steam Deck やタッチ対応ノート PC がスマホ扱いになり、ポインターロック無効・タッチボタン表示・低画質で始まる | `Input.ts:37` | 必須 | ― |
| 1-4 | キー割り当ての変更ができない（`BINDINGS` が定数）。Shift と Ctrl が 2 つの操作に重なっている | `Input.ts:5-33` | 重要 | 要件は残る |
| 1-5 | メニューのフォーカス移動が弱い。初期フォーカスやフォーカストラップがなく、`<li onClick>` などマウス専用の要素がある。Tab キーを図鑑に使っているため Tab でのフォーカス移動とぶつかる | `HomeMenu.tsx:91`、`SpotSelect.tsx:62`、`TankPanel.tsx:132`、`Root.tsx:179`、`Input.ts:18` | 重要 | 要件は残る |
| 1-6 | 観察・水槽・図鑑プレビューのカメラは `OrbitControls` で、スティック入力がない | `Observation.ts`、`TankScene.ts`、`ModelPreview.ts` | 重要 | ― |

直し方の方針: `src/core/Input.ts` にゲームパッドの入力源を足し（スティック → `setTouchMove` と同じ経路、ボタン → Action）、画面ごとに「パッドでの選択カーソル」を持たせる。判定は「最後に使った入力機器」で切り替え、タッチ判定は実際のタッチイベントが来てから有効にする。

## 2. セーブ

| # | 内容 | 場所 | 区分 | 移行後も残るか |
|---|---|---|---|---|
| 2-1 | 保存先は IndexedDB（idb-keyval の既定ストア）。**オリジンが変わると消える**。Electron で `file://` → 独自プロトコルに変える、ポート番号が変わる、などで既存のセーブが見えなくなる。Steam Cloud にも載らない | `Save.ts:46-48`、`Settings.ts:83-147` | 重要 | 形式は残る |
| 2-2 | 終了時の保存は `beforeunload` での非同期書き込みで、アプリ終了時に書き切れる保証がない | `App.ts:137-141` | 重要 | ― |
| 2-3 | 書き出し（`<a download>`）と読み込み（隠し `<input type=file>`）、`confirm()` / `alert()` がブラウザー頼み。Tauri・iOS・Android では動かないか見た目が崩れる | `App.ts:1559-1568`、`Menu.tsx:48-63`、`App.ts:284` | 重要 | ― |
| 2-4 | セーブ形式は `version: 1` 固定で、移行（migration）の仕組みがない。Steam とスマホでセーブを共有すると、古い版のアプリが新しいセーブを拒否する | `Save.ts:70-122` | 軽微（共有するなら重要） | 残る |

よい点: セーブは `SaveV1` という 1 つの JSON で、書き込みは直列化、旧データはバックアップに回り、読めないデータは別に保管して復旧画面を出す（`Save.ts:137-208`）。**`SaveStore` の get / set をファイル書き込みに差し替えるだけで Steam Cloud に対応できる**。大きさは数十〜数百 KB の見込み（図鑑の個体記録だけは上限なしで少しずつ増える）。

## 3. 時刻・潮汐・通信

| # | 内容 | 場所 | 区分 | 移行後も残るか |
|---|---|---|---|---|
| 3-1 | **時刻は常に日本時間（UTC+9）**。潮位は UTC から計算しているので正しいが、欧米のプレイヤーが夜に遊ぶと日本の未明になる。潮時チケット（好きな日時を 30 分遊べる）が実質的な逃げ道 | `Time.ts:1-37`、`GameClock.ts:32-38` | 重要（海外販売の設計問題） | **残る（設計の決めごと）** |
| 3-2 | 潮時チケットは使用回数を数えるだけで、制限がない。今は問題ないが、日替わり報酬などを足すと時計の巻き戻しで不正ができる | `App.ts:584`、`App.ts:306-309` | 軽微 | 残る |
| 3-3 | **デバッグパネルで時刻を自由に変えられ**、PC では `?debug` かキーで開ける | `GameClock.ts:41-43`、`DebugPanel.tsx`、`App.ts:265,1640` | 重要 | ― |
| 3-4 | 起動 4 秒後と 10 分ごとに `version.json` を取りに行き、違えば「再読み込み」を出す。パッケージ版では不要（更新は Steam やストアが行う） | `Build.ts:34-45`、`App.ts:250-252` | 重要 | ― |
| 3-5 | データの読み込みは `fetch` で、`file://` では動かない。ローカルのサーバーか独自プロトコルが必要。`VITE_BASE` も `/gerupamasini/` から変える | `loader.ts:19-22`、`Terrain.ts:24`、`vite.config.ts:8` | 重要 | ― |

よい点: 潮汐は `src/tide/`（Meeus の天文計算と 37 分潮）で端末内で計算し、定数は同梱 JSON（1 観測点 約 5 KB）。**ゲームの動作に通信は要らない**。年の上限もない（遠い年ほど精度が落ちるだけ）。

3-1 の案（どれにするかは決める必要がある）:
- A. 今のまま日本時間。チケットを常に使えるようにして、「今の日本の潮」と「好きな潮」を対等な遊び方として見せる
- B. 「現地時間に合わせる」モード。潮汐は実際の日本の値のまま、表示と昼夜だけをずらす（現実との連動は弱まる）
- C. 地図ごとに「日本の何日前の潮」を選べる時差モード

## 7. Steam・ストアの手続きで新しく作るもの

コードの外の作業。エンジンを何にしても必要。

- **Steamworks**: 実績（図鑑の登録数、種ごとの初採集など）、Steam Cloud（セーブ 1 ファイル + 設定）、リッチプレゼンス（「走水で干潮を観察中」）
- **ストアページ**: カプセル画像、トレーラー、スクリーンショット。早めに「近日登場」で公開してウィッシュリストを集める
- **体験版**: Steam Next Fest への出品
- **Steam Deck**: 認証の項目（パッド操作、文字の大きさ、初期設定のままで遊べること、オフラインで動くこと）
- **スマホ**: 年齢レーティング（IARC）。有料ガチャにするなら確率の表示、景品表示法（コンプガチャの禁止）、Apple・Google の規約を確認する

## 8. 着手の順番（Three.js のまま進める場合）

エンジン移行を決めた場合、1〜3 の大半は捨てる作業になる。その場合も 4 と 5 は残る。

1. パッケージ化の土台: Electron + `VITE_BASE=./`、独自プロトコルでのデータ配信、セーブのファイル化、終了時の保存、更新確認を止める、デバッグ機能を外す、フォントの同梱
2. 入力: ゲームパッド、Deck の判定、水槽・ショップのパッド選択、メニューのフォーカス
3. UI: 文字の拡大、全画面・FOV・音量の設定、ネイティブのダイアログ
4. **どのエンジンでも必要**: 効果音と環境音の収録・制作、文言の文言表への移動と英訳、日本時間をどう扱うかの決定
5. **どのエンジンでも必要**: テクスチャの圧縮パイプラインと、実機での性能計測
