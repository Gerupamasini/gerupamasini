対象: ブランチ `claude/adoring-faraday-h25n7c`、コミット fccf531
目的: 既存モデルをゲームへ組み込むための前提確認と、3D モデル仕様書の土台

## 1. 資産の概要

- `models/mahaze_juvenile.glb` 19.4 MB。glTF 2.0。`KHR_mesh_quantization` が必須拡張。`KHR_materials_transmission` / `volume` / `ior` / `clearcoat` を使用。
- 単位はメートル。+Y 背側、+Z 吻端方向、+X は魚の左。全長 50.5 mm、標準体長 41 mm の幼魚。
- ノード 38、メッシュ 12、マテリアル 4、スキン 1（24 関節）、アニメーション 3、テクスチャ 11。
- three.js r186 を vendor 同梱。npm 依存はビルド用の jpeg-js のみ。

## 2. リグとクリップ

- 関節 24: J_root, J_head, J_suspL/R, J_jawL/R, J_premax, J_hyoid, J_opercL/R, J_eyeL/R, J_pecL/R, J_pelvic, J_sp1〜J_sp7, J_caudal, J_caudal2。
- 体軸チェーン（`SPINE`）: J_head(9mm), J_root(13), J_sp1(16.5) … J_sp7(40), J_caudal(43), J_caudal2(46.5)。静止姿勢は全関節が単位回転。
- ひれのモーフターゲット順は `src/fish/pose.js` の `FIN_TARGETS` で固定（fold / flex / waveS / waveC）。
- クリップ: `Idle` 3.48 s ループ 30fps、`Swim` 0.125 s ループ 240fps（尾の 1 拍）、`Yawn` 2.4 s ワンショット。各 33 チャンネル（回転・平行移動・モーフ重み）。
- glTF extras: マテリアルの `extras.mahaze`（role、色素テクスチャ、吻端キャップ、fishFrame、椎骨範囲、断面プロファイル表）。ルートノードの extras に種名、単位、`mahazeRig.axes`（手続き駆動用の回転軸）、接地高さ。

## 3. 描画と実行時の前提

- WebGL2 と `EXT_color_buffer_float` が必須。
- ビューアの描画順: 背景バッファ（不透明シーン + 奥のひれ）→ 本描画（MSAA、HalfFloat HDR）→ ポスト（ブルーム、ACES、ビネット）。
- `BodyMaterial` は背景バッファ `uBg`（色 + 視距離）を読み、組織をレイマーチして透過と逆光を計算する。したがって組み込み先でも「ヒーロー個体の背後のシーンを先に描いたバッファ」を渡す必要がある。
- ひれは透過と散乱の 2 パスで、毎フレーム奥から順にソートする。口内・歯・鰓は同じスケルトンでスキニング。
- 共有ユニフォーム: 光方向と色、水の色 3 種、環境光、フォグ、時間、散乱、内部構造、コースティクス、床の高さ、背景、解像度。ゲーム側の照明系と接続する必要がある。
- 標準フォールバック: glTF の PBR（透過と体積）を `MeshPhysicalMaterial` とライトで表示する切替がすでにある。これが標準 LOD の材質になる。
- マクロ観察のためカメラの near は 0.0004 m。ゲームではログ深度か、観察モード時の near/far 切替が要る。

## 4. 行動

- `src/fish/Behavior.js`: perch / paddle / orient / dart / glide / yawn の状態遷移。休止は重い裾の分布で 10〜30 秒、ときに 1 分超。左右独立の眼のサッカード、毎分 70 回の換水、警戒姿勢、胸びれの扇ぎ。
- `src/fish/pose.js`: ビルド時のクリップ焼き込みとビューアの手続き駆動の両方で使う共通の姿勢モデル。
- インターフェース: `createBehavior({ root, bones, finMeshes, axes, contacts, floorY })` が `update(dt)`, `dart()`, `yawn()`, `flick()`, `paddle()`, `pose()`, `anchor()`, `setAuto()`, `setPaused()`, `state` を返す。`update` は dt を 1/20 秒で頭打ちにするので、スロー再生は dt を縮めれば成立する。

## 5. ビルドパイプライン

- `node tools/build-model.mjs [--fast] [--dump-textures dir]`。約 1 分。
- 可変パラメータ: 胴体ロフト分割（NS 460 × NV 224、`--fast` で半分）、テクスチャサイズ、虹彩サイズ。ひれの分割（SUB 6、NT 36〜44）は固定値なので LOD 用に引数化が必要。
- クリップは `pose.js` から生成されるため、ビューアの手続き駆動と常に一致する。

## 6. ゲームへの組み込み方針（提案）

3 段階の表示品質を持たせる。リグ名とクリップ名は全段階で共通にし、ドライバを 1 本で済ませる。

| 段階 | 対象 | ジオメトリ | 材質 | 駆動 | 同時数の目安 |
|---|---|---|---|---|---|
| ヒーロー | 観察ロック中の 1 体、水槽ビューの 1 体 | フル（口内を含む） | 独自シェーダー | 手続き（Behavior.js） | 1 |
| 標準 | 近距離 | フル、口内なし | 標準 PBR フォールバック | 手続きまたはクリップ | 〜20 |
| 遠景 | それ以外 | ビルダーの低分割版（目安 4k 頂点以下、テクスチャ 512） | 標準 PBR、ひれは alphaTest | クリップ、更新間引き | 〜200 |

ビルダーへ足すもの: `--lod N` プリセット、`--no-interior`、出力名の段階別化。
ゲーム側の描画: 地形・水・非ヒーロー個体を先に RT へ描き、それを `uBg` としてヒーロー個体に渡す。ビューアと同じ構成。
直すべき点: 全メッシュ `frustumCulled = false` は 1 体なら良いが群れでは不可（段階ごとに境界を計算する）。毎フレームのひれソートはヒーローのみ。`window.MAHAZE_MODEL_URL` のグローバルはローダー引数に置き換える。vendor の three.js は npm に置き換える。
成魚: 現状は幼魚のみ。ビルダーの解剖パラメータを変えた成魚プリセットは別作業。MVP では幼魚モデルのスケールと色調で代用する。
