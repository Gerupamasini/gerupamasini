# 図鑑の画面改善

分類ごとの索引と生物の詳細を分け、名前検索・分類・干潟・発見状況を組み合わせて絞り込めます。名前検索は、ひらがな・全角／半角カタカナに対応します。発見済みの種は学名・英名でも検索できます。

未発見種は和名だけを表示し、画像・3Dモデル・学名・性差・生態・生息環境・行動名・採集記録を表示しません。干潟の絞り込みはゲームの出現設定に基づき、季節や潮位を問わず一覧を探せます。生物無効のマップ（現在の漫湖）には該当種を表示しません。マガキの出現データも実際に牡蠣礁がある葛西だけに合わせ、走水に誤表示しないようにしました。

PCは索引と詳細の2ペイン、スマホは一覧から詳細への切り替えです。一覧に戻ると絞り込み条件を維持します。詳細は「生態」「行動」「採集」を切り替え、長い情報を一度に並べません。分類見出しに発見数、上部に全体の進捗を表示します。超軽量画質は既存モデルの静止画像、その他の画質は回転・拡縮できる既存の3Dプレビューです。スマホの一覧ではプレビュー用のWebGLコンテキストを作りません。

Esc／閉じるボタンで元の画面に戻ります。図鑑内のTabはフォームやボタンの移動に使い、ゲームの図鑑切り替え操作と競合しないようにしました。表示変更にセーブ形式の変更はありません。

## 次に加えるとよい変更（提案・未実装）

1. **出会いやすい条件**：発見済みの種に季節・時間帯・潮の目安を表示。既存の出現設定から作成し、次回の探索に役立てる。
2. **探したい生物のしおり**：次に探す種を数件保存し、候補の干潟へ移れる導線を追加。未発見種は名前だけの表示を維持。
3. **観察履歴**：初発見日・最後に観察した日・干潟名を記録。干潟ごとの「出現する種」と「自分が出会った種」を分けて表示する。今の個体記録は採集地点の座標を持ちますが、干潟IDを持たないため、位置履歴には新しい記録・セーブ移行の設計が必要です。
4. **行動コンプリートの導線**：行動未記録の種だけの絞り込みと、次に観察したい行動の選択。発見率に加えて観察を深める目標にする。

## 検証

`npm run check`、`npm run build`、`npm run smoke:zukan`、`npm run smoke:recovery`。

新しい図鑑のブラウザ検証は分類・干潟・発見状態・検索の組み合わせ、未発見情報の非表示、行動記録、採集個体、Tab／Esc、静止画像と3D表示の切り替えを扱います。スマホは390×844、320×568、844×390、768×1024で、一覧／詳細の往復と画面内への収まりを確認します。Chromiumで検証し、スクリーンショットはテスト用の発見記録で撮影しています。スマホの3D表示は端末回転後のアスペクト比も確認します。
