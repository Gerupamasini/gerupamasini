## 1. リアル潮位システム

### 1.1 方式
調和分解による予測。観測点の調和定数（分潮ごとの振幅 H と遅角 κ）から任意時刻の潮位を計算する。完全オフライン。観測実測値は使わない。

```
η(t) = Z0 + Σ_i f_i(t) · H_i · cos( V_i(t) + u_i(t) − κ_i )
```

- `Z0`: 平均海面。ゲームでは平均海面を 0 とするので、平均海面基準の潮位は `η − Z0`。
- `V_i(t)`: 分潮 i の天文引数。Doodson 数 (i1..i6) と位相定数 φ_i から `V = i1·τ + i2·s + i3·h + i4·p + i5·N' + i6·p' + φ`。
- `f_i, u_i`: 18.6 年周期の節点補正（振幅係数と位相補正）。
- `κ_i`: 遅角。気象庁と海上保安庁の表は日本標準時（東経 135 度）基準。天文引数は 135 度子午線での値を使う。実装では `τ` を世界時で計算し、`i1 × 135°` を加える。符号規約は 1.4 の検証で確定する。

### 1.2 天文引数（度、T はユリウス世紀、J2000.0 から）
```
s  = 218.3164477 + 481267.88123421·T − 0.0015786·T²      月の平均黄経
h  = 280.46646   + 36000.76983·T    + 0.0003032·T²       太陽の平均黄経
p  = 83.3532465  + 4069.0137287·T   − 0.0103200·T²       月の近地点
N  = 125.0445479 − 1934.1362891·T   + 0.0020754·T²       月の昇交点（N' = −N）
p' = 282.93735   + 1.71946·T                              太陽の近地点
τ  = 15·(世界時の時) − s + h                               平均月時角
```

### 1.4 検証（受け入れ基準）
- 気象庁の潮位表（予測値、毎時）と同じ日について比較し、4 分潮版で RMS 誤差 15 cm 以内、60 分潮版で 5 cm 以内。満干潮の時刻差は 4 分潮版で 20 分以内。
- 符号規約（κ と 135 度補正、φ の符号）は、この比較で確定する。比較データが取得できない間は、Yahoo 天気などの東京の満干潮時刻と目視で突き合わせる。
- 単体テストに固定日時のサンプルを持ち、回帰を検出する。

### 1.5 ゲームへの反映
- 水面の高さ = 平均海面 (T.P. 0 とみなす) + 潮位偏差。1 秒ごとに更新し、フレーム間は線形補間。
- 地形は T.P. 高さを持つ。深さ = 水面 − 地形高さ。負なら露出。
- 濡れ: 露出した地点は直近の水没からの経過時間で乾く（泥 2 時間、砂 40 分）。描画の反射率と色、Habitat の `wetness` に使う。
- 潮だまり: 地形の局所的な凹みは、水面がその縁より下がっても縁の高さまで水を残す（セルごとに「縁高さ」を事前計算）。
- 歩行可否: 深さ 0.35 m を超える地点は進入不可。深さに応じて減速。
- 上げ潮・下げ潮: 潮位の時間微分の符号。HUD の矢印と出現条件 `tide` に使う。
- HUD の潮位ゲージ: 現在時刻の前後 12 時間の潮位曲線と満干潮の時刻。

## 2. 時間系

### 2.1 GameClock
- `nowReal()` は `Date.now()`。`nowGame()` はチケット中のみ再現時刻を返す。
- 潮位、太陽、季節、出現条件はすべて `nowGame()` を使う。セーブの時刻印と自動保存は `nowReal()`。
- 表示はすべて JST。`Intl.DateTimeFormat('ja-JP', { timeZone: 'Asia/Tokyo' })` で整形。

### 2.2 太陽
- NOAA の太陽位置近似で、地図の緯度経度から太陽高度と方位を計算。空の色、方向光の色と強さ、環境光を高度の関数で決める。
- `timeOfDay`: 高度 > 6° で day、−6°〜6° で dusk / dawn（午前午後で判定）、それ以下で night。

### 2.3 季節
日付から春 (3〜5)、夏 (6〜8)、秋 (9〜11)、冬 (12〜2)。

## 3. 潮時チケット

### 3.1 ルール
- 使用時に現実時刻の前後 3 日の範囲で日時を選ぶ（10 分刻み）。季節は変えられない。
- 効果時間はリアル 30 分。ポーズ中（メニュー、タブ非表示）は停止。
- 残り時間はセーブに保存。再起動後も継続する。
- 終了 60 秒前に通知。終了すると 10 秒かけて現実時刻へ遷移（水位と太陽を補間）。
- 使用中に別のチケットは使えない。手動で中断可（枚数は戻らない）。
- テスト版は枚数無制限。配布ルールは翌週以降。
- 季節の潮時チケット（将来）: 季節を 1 つずらした同じ日付を選べる。

### 3.2 時刻の根拠と巻き戻し検知
- PC 時計を信用する。セーブには `lastRealMs` を記録。
- 起動時に `Date.now() < lastRealMs − 5 分` なら時計の巻き戻しとみなし、使用中のチケットを無効化し、日次配布のカウンタを凍結する。表示は「時計がずれています」の警告のみ。
- サーバー時刻の確認は、将来ランキングを入れる時に `timeSource` の実装を差し替えるだけで済む構造にする。

### 3.3 状態遷移
```
idle → (useTicket) → active{remaining=1800} → (pause) → paused → (resume) → active
active → (remaining<=0 or cancel) → ending{10s 補間} → idle
```

## 4. セーブ設計

### 4.1 保存先
IndexedDB（idb-keyval）。ストア `higata`、キー `save:slot1`、`settings`、将来 `photos:*`。

### 4.2 スキーマ v1

```ts
interface SaveV1 {
  version: 1;
  createdAt: number; updatedAt: number; lastRealMs: number;
  player: { map: string; pos: [number, number, number]; heading: number; money: number; research: number; tools: string[] };
  ticket: { active: TicketState | null; usedCount: number };
  encyclopedia: Record<string, {
    discovered?: number; observed?: number; captured?: number; maleSeen?: number; femaleSeen?: number;
    behaviors: Record<string, number>;            // behaviorId → 初記録の時刻
    individuals: IndividualRecord[];               // 採集個体
  }>;
  case: IndividualRecord[];                         // 観察ケース
  tank: { individuals: IndividualRecord[]; lastSimMs: number };
  removedIndividuals: string[];                     // 採集済みでスポーンさせない個体 ID
  stats: { playSeconds: number; captures: number; observations: number };
}
interface IndividualRecord { id: string; speciesId: string; length_mm: number; weight_g: number; sex: 'm'|'f'|'unknown'; stage: string; traits: string[]; caughtAt: number; caughtWhere: [number, number]; tideLevel: number }
```

### 4.3 運用
- 自動保存の契機: 図鑑更新、採集、ケースから水槽へ移動、チケット使用と終了、60 秒ごと、タブ非表示時。
- 書き込みは直列化し、直前の内容と同じなら書かない。
- 読み込み時に `version` を見てマイグレーション関数を順に適用する。
- エクスポートは JSON ファイルのダウンロード、インポートは検証後に置き換え。
- 将来の Tauri 版はファイル保存へ差し替え。`SaveStore` インターフェースで分離する。

## 6. 水槽（MVP）
- Tank シーン。明るい水槽環境、砂底、周回カメラ。ケースから 1 匹を入れる。
- 入れた個体はマハゼドライバで行動する。観察モードと同じ行動記録が働く。
- 時間進行: `tank.lastSimMs` を記録し、帰宅時に経過時間を読む。MVP ではシミュレーションしない。将来は経過時間分の空腹と行動統計を近似する。
