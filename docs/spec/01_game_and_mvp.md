## 1. 確定事項（要約）

| 項目 | 決定 |
|---|---|
| リリース | Web で開発、後から Steam（Tauri でラップ） |
| 対象性能 | 内蔵 GPU で 30fps、ゲーミング PC で 60fps。品質 3 段階 |
| サーバー | MVP はなし。将来ランキングと写真共有だけ軽量サーバー |
| 収益 | 未定。決済とアカウントに依存しない設計 |

| 移動 | 歩く・走る・しゃがむ。水は長靴の高さまで。泳ぎなし |
| 入力 | キーボード + マウス。ゲームパッドは入力抽象層で後付け |
| 舞台 | 葛西西なぎさをモデルにした架空の干潟、約 300 m 四方。潮位は気象庁「東京」 |
| 潮位 | 調和定数から自前計算、完全オフライン |
| 時間 | 現実の JST。潮時チケットで前後 3 日の任意時刻を 30 分再現 |
| 生物（MVP） | マハゼ（採集可）、シラタエビ（採集可）、シロチドリ（観察のみ） |

| 採集 | 道具ごとの短いインタラクション。MVP は手網のみ |
| 観察 | ロックオン周回カメラ、マクロ、0.25〜2 倍速 |
| 図鑑 | 種登録は採集時（採集不可種は観察時）。行動記録は観察モードでロック中の発生時 |
| 写真 | 画像保存 + 簡易評価（MVP 対象外） |

## 2. コンセプト

「現実の潮汐と連動する干潟を探索し、実物に限りなく近い 3D 生物を探し、観察・撮影・採集・飼育して、自分だけの生物図鑑と水槽を完成させるゲーム」。

4 本柱: REAL TIDE、REAL CREATURE、REAL BEHAVIOR、COLLECT。
ゲームとしての楽しさとプレイしやすさを、リアリティと両立させる。リアリティのために操作を煩雑にしない。

## 3. ゲームループ（改訂版）

1. 現実の時刻と潮位を確認する（タイトル画面と HUD に潮位グラフ）。
2. 干潟へ出る。潮位に応じて歩ける範囲、水深、露出した泥、潮だまりが変わる。
3. 探索する。痕跡と環境から生物を探す。
4. 観察モードで近づき、行動を記録する。採集可の生物は手網で採集し、観察ケースへ入れる。
5. 図鑑に自動登録される（種、個体、行動）。
6. 任意のタイミングで自宅へ戻る。ケースの生物を水槽へ移す。帰宅は毎周回の必須ではない。
7. 水槽で生物を眺め、干潟では見にくい行動を観察する。
8. 研究ポイントとお金を得て、道具・水槽・地域・機能を解禁する。
9. 潮時チケットで別の潮位の干潟を再現し、再び探索する。

満潮時の遊び: 満潮時にしか出ない生物と行動（遊泳魚の群れ、鳥の採餌）を用意し、待ち時間を別の遊びにする。MVP ではシロチドリが満潮前後の水際で採餌し、マハゼが浅い水中で活動する。

## 4. 世界

### 4.1 干潟「西のなぎさ」（仮称）

- 葛西西なぎさをモデルにした架空の人工渚。名称は架空。
- 範囲は 320 m × 320 m。北端が砂浜の高み（T.P. +2.0 m）、南へ 1/80 前後の緩い勾配で下り、南端は T.P. −1.5 m。
- 底質は北から砂、砂泥、泥へ移行。西側に澪（細い水路）が 1 本あり、泥底で干潮時も水が残る。下部の平坦面に浅い潮だまりが 3〜5 か所。
- 地形は手続き生成（シード固定）。ハイトマップ PNG と底質マップ PNG に書き出して保存し、以後はデータとして読む。
- 潮位は気象庁「東京」の調和定数から計算し、水面は平均海面を基準に上下する。満潮と干潮で汀線が 150 m 以上動く。
- 立入不可の保護区（東なぎさ相当）は将来の拡張として地図データに枠だけ用意する。

### 4.2 時間

- ゲーム内時刻は現実の JST。太陽位置と空の色は時刻と日付から計算する。
- 季節は日付から判定（春 3〜5、夏 6〜8、秋 9〜11、冬 12〜2）。
- 潮時チケット: 使用すると前後 3 日の任意の時刻を選び、30 分間その時刻の潮位と太陽を再現する。リアル時間で計測、ポーズ中は停止、残り時間はセーブに保存、終了後は現実時刻へ復帰。季節は変えられない。
- 季節の潮時チケット（将来）: レア報酬。季節を 1 つずらす。
- MVP テスト版ではチケット枚数を無制限にする。

## 5. プレイヤー

- 一人称。目の高さ 1.6 m、しゃがみ 0.9 m。
- 歩行 1.4 m/s、走行 3.0 m/s、しゃがみ 0.7 m/s。泥底では 0.6 倍。
- 水深が長靴の高さ 0.35 m を超える場所へは進めない。水深に応じて減速。
- 画面中央のレティクルで対象を指す。対象が採集可なら E、観察可なら F が表示される。
- 観察ケース: 採集した個体を持ち運ぶ。MVP の容量は 6。

## 6. 生物（MVP 3 種）

| 種 | 分類 | 採集 | モデル（金曜版） | 主な行動 | 出現 |
|---|---|---|---|---|---|
| マハゼ | 魚 | 可（手網） | 既存の写実モデル（幼魚）。成魚はスケールと色調で代用 | 着底休止、位置直し、ダッシュ、滑空、あくび、警戒姿勢、逃走 | 浅い水中と潮だまり、砂泥底、水深 0.05〜1.0 m、昼夜 |
| シラタエビ | 甲殻類 | 可（手網） | 手続き生成の簡易モデル | 歩行、遊泳、摂餌、後方跳躍で逃走 | 浅い水中と潮だまり、砂泥底、水深 0.03〜0.6 m、夜に多い |
| シロチドリ | 鳥 | 不可（観察のみ） | 手続き生成の簡易モデル | 歩行、走行、ついばみ、見張り、短い飛行で離脱 | 露出した砂泥面と水際、干潮前後、昼 |

個体情報: 全長、重量、性別、成長段階、特徴タグ（大型個体など）。種データの分布から生成する。マハゼの表示例: 「マハゼ #0284 全長 14.7 cm 重量 31.2 g ♂ 成魚 大型個体」。

## 7. システム

### 7.1 観察モード
- レティクルで生物を指して F。カメラが対象の周りを回る周回カメラへ切り替わる。マウスドラッグで回転、ホイールで接近。最接近は眼のマクロまで。
- 速度は 0.25、0.5、1、2 倍。対象のロック中に発生した行動は図鑑に記録される。
- ロック中の対象はヒーロー品質で表示する（マハゼのみ、翌週版）。金曜版は標準 PBR 表示。
- Esc か F で解除。

### 7.2 採集（手網）
- レティクルで採集可の生物を指して E。短いタイミング操作が始まる。
- 画面にゲージが動く。生物の警戒度が高いほど成功帯が狭い。成功帯でクリックすれば採集、失敗すると生物は逃走する。
- 採集した個体は観察ケースに入り、図鑑に種と個体が登録される。
- 生物へのダメージ表現はない。

### 7.3 図鑑
- 種ページ: 名前、学名、分類、解説、生息環境、出現条件のヒント、採集可否。
- 進捗: 発見、観察、採集、♂ 発見、♀ 発見、行動項目ごとの記録。
- 個体記録: 採集した個体の一覧。最大、最小の個体を表示。
- 仮モデルの種は「仮モデル」と明示する。

### 7.4 水槽（MVP）
- ホーム画面。採集ケースの個体を 1 匹選んで水槽へ入れる。
- 明るい水槽環境で周回カメラ。マハゼはヒーロー表示（翌週版）、金曜版は標準 PBR。
- 複数個体、レイアウト、水質はなし。

### 7.5 進行
- 研究ポイント: 初発見 100、初採集 50、行動の初記録 30、性別の初確認 20。
- お金: MVP では表示のみ。
- 解禁: MVP ではなし。

### 7.6 セーブ
- IndexedDB に自動保存。保存の契機は図鑑更新、採集、帰宅、チケット使用、60 秒ごと。
- 1 スロット。JSON のエクスポートとインポート。

## 8. MVP の範囲

### 8.1 金曜版（10/2 配布）
必須:
- タイトル、読み込み画面、HUD（時刻、潮位ゲージ、道具、ケース数）
- 干潟 1 面、潮位連動の水面、昼夜
- 一人称移動と水深制限
- 3 種のスポーン、簡易 AI（03 参照）、マハゼの標準表示と遠景表示
- 観察モード（周回カメラ、速度変更、行動記録）
- 手網による採集
- 図鑑（種、進捗、個体）
- 水槽ビュー（1 匹）
- セーブ、潮時チケット（無制限）
- GitHub Pages で配布

あれば:
- マハゼのヒーロー表示（観察ロック時と水槽）
- 足音と波の環境音

入れない:
- 写真、ショップ、水槽カスタマイズ、研究ポイントの消費、天候、サーバー、ゲームパッド、シラタエビとシロチドリの写実モデル

### 8.2 翌週版
- マハゼのヒーロー表示統合、マハゼ成魚プリセット
- シラタエビ写実モデル、シロチドリ写実モデル
- 写真撮影と保存、簡易評価
- 水面の反射と屈折、濡れた泥
- 痕跡（巣穴、足跡、這い跡）
- 潮時チケットの配布ルール

## 11. テスト計画（MVP）

- 単体: 潮位計算（既知の潮位表との比較、許容 RMS 10 cm 以内）、時計とチケットの状態遷移、出現条件の評価、セーブの往復。
- 描画: ヘッドレス Chromium で起動し、スクリーンショットで地形・水面・生物の表示を確認。
- 手動: テスト手順書に沿って一周（開始、潮位確認、マハゼ発見、観察、採集、図鑑、水槽、チケット、再読み込みで復元）。
- 性能: 内蔵 GPU 相当の設定で 30fps を目安。dpr 1、低品質プリセット。

## 12. 将来の拡張方法

- 種の追加: 種 JSON、行動ツリー JSON、モデル 3 段階、ドライバ（必要なら）を追加。コード本体の変更なし（03 参照）。
- 地域の追加: ハイトマップ、底質マップ、地図 JSON、潮位観測点 JSON を追加（02 参照）。
- 水槽の拡張: 水槽をもう 1 つの「地図」として扱い、同じスポーンと AI を使う。干満水槽は潮位源を差し替えるだけで成立する。
