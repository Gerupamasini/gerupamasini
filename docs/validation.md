# Visual / Biological Validation — シロチドリ

すべての画像は `docs/validation/`。再現コマンド:
- 形状シート: `node tools/validate.mjs sheet_stand=pose=stand`（側面・正面・上面を 1 cm グリッド上に正射影）
- アクションのコマ送り: `node tools/validate.mjs strip_walk="mode=strip&pose=walk&frames=6&cyc=1"`
- 寸法: `node tools/dev/measure.mjs` / 翼の体表からの浮き: `node tools/dev/poke.mjs`
- 行動統計: `node tools/dev/simulate.mjs 480 10 1`
- 歩行・走行中の体のがたつき: `node tools/dev/gaitjitter.mjs`（実際の表示タイミングで駆動し、追従カメラに対する体の動きを計測。§3b）

## 0. 重要な制約（正直な記載）

**参考写真と並べた比較は実施できていない。** この環境では外部通信が npm/GitHub 以外遮断されており、写真・動画を取得できなかった（research.md §0）。そのため検証は次の3つで代替した:
1. 計測値・比率（research.md の文献値）との**数値比較**
2. 文献の**文章記述**（羽色の配置、「胸帯は決して完全にならない」、「翼端は尾端付近」等）とのチェックリスト照合
3. 生体力学的な妥当性（接地・IK・関節の可動方向）のコマ送り目視

写真・動画が使える環境では、`validation.html?mode=silhouette` の黒シルエットを実写の側面写真に重ねて比較する手順を推奨する（§6）。

## 3b. 歩行・走行中の体のがたつき（`gaitjitter.mjs`）

「歩く速さと脚の動きは良いが、体ががくがくする」という指摘への対応。追従カメラ（毎フレーム鳥の位置差分だけ動く）に対する体（body 骨）の位置の2階差分 ＝ 画面上で見える「がたつき」を、実際のフレーム時刻（60 Hz ±0.3 ms の揺らぎ＝`60j`、30/120/144 Hz）で計測した。

| 場面 @表示 | 骨更新なしフレーム | 描画ルートの遅れ 最大 | 体のがたつき RMS / 最大（mm/フレーム） | 走行中の体の上下動 | 発進・停止の前傾 / ピッチ角速度 |
|---|---|---|---|---|---|
| アニメ viewer 走行 @60j | 35% → 0% | 21.9 → 0 mm | 33.6 / 43.9 → 0.34 / 0.50 | 4.2 mm @21 Hz → 0.18 mm | — |
| アニメ viewer 歩行 @60j | 35% → 0% | 4.2 → 0 mm | 6.5 / 8.5 → 0.22 / 0.32 | 1.2 mm @6.8 Hz（変更なし） | — |
| AI（デモ既定、追従）@60j | 36% → 0% | 28.6 → 0 mm | 28.4 / 57.2 → 0.33 / 2.0 | — | 6.6° / 133°/s → 2.0° / 25°/s |
| AI @144j | 67% → 0% | 24.8 → 0 mm | 19.7 / 37.3 → 0.08 / 0.98 | — | 6.5° / 211°/s → 2.0° / 25°/s |
| 走行を 12 m から追従（LOD2）@60j | 61% → 50%（規則的な 30 Hz） | 43.7 → 0 mm | 50.1 / 66.2 → 0.45 / 0.65 | — | — |

原因と対策:
1. **骨更新の間引き（主因）**: LOD0/1 は `animRate 60` で「累積時間 ≥ 1/60 s」のときだけ更新していたため、フレーム時間の揺らぎで約 1/3 のフレーム（120/144 Hz 表示では 2/3）で骨もルートも更新されず、毎フレーム動く追従カメラに対して鳥全体が最大 v·dt（走行 22 mm）前後に跳んでいた。→ LOD0/1 は毎フレーム更新（optimization.md の設計どおり）。間引く LOD2 は揺らぎに強い判定にし、間のフレームもルートは個体位置に追従。
2. **走行時の体の上下動**: 2.5 mm・19 Hz（60 fps で 1 周期 3 コマ）が振動に見えた。→ 体幹の加速度を 1.5 m/s² に制限（歩行の 1.2 mm はそのまま、走行 ≈0.2 mm）。
3. **加速度による前傾**: 発進・停止のたびに約 6° を 100°/s 以上でうなずいていた。→ 入力を平滑化し利得を下げて約 1.5–2°。
4. **地形の段差**: 干潟の澪筋（creek）の上端 z = 34 m で `heightAt` が最大 25 cm 不連続で、鳥の群れが採餌する場所を横切ると鳥（と追従カメラ）が瞬間移動していた。→ 上端 2 m で深さを 0 に漸減（`Terrain.js`）。

脚は変えていない: トレッドミル（全表示レート）とアニメ viewer（揺らぎなし 60 Hz・30 Hz）で足の着地目標・足関節の軌跡は変更前と **0.000 mm** 一致、ストライド周波数・デューティ比・足の最大高・速度も同一。足根間関節の位置だけが体の高さの変化分（≈1 mm）動く。以前は間引きのせいで揺らぎのある表示では着地位置が最大 v·dt ずれていた（その分は今回なくなった）。
残り: 静止からの発進時、目標方向への素早い旋回の立ち上がりで体が 1–2 mm 横に振られる（AI 60j で 2.7% のフレーム）。旋回の速さはチドリの急な方向転換として残した。

## 5. 残っている課題（未解決を明記）

1. **翼開長が図鑑値より約10%短い**（383 vs 420–450 mm）。翼長 108 mm（信頼度A）と、畳んだ時に翼角が胸側に収まる骨長（推定D）を優先した結果。骨格標本の上腕骨・尺骨長の実測が得られれば解決できる。
2. 最大幅が目標上限を約 3% 超える（小雨覆の厚み）。
3. 羽色の RGB は文章からの推定。照明条件の異なる写真での校正が必要。
4. 歩行・走行・探索時間の数値は動画解析ではなくスケーリング則とシミュレーションによる。
5. 眼は近接でやや「レンズ」的に見える（角膜反射の形状）。実写の眼のクローズアップとの比較が必要。

## 6. 写真比較の手順（通信制限のない環境で実施すること）
1. `validation.html?mode=silhouette&pose=stand` で黒シルエット（側面 1 cm グリッド）を出力
2. 真横から撮影された成鳥雄夏羽の写真を、跗蹠長 28 mm でスケール合わせして重ねる
3. 頭頂高・胸の張り・尾の突出・脚の付け根位置のずれを mm で記録し、`KentishPloverConfig.bodySculpt` を調整
