# 沖縄浅海用サンゴ

新ブランチ `feat/okinawa-coral-reef`。5つの代表的な造形を、各4形状・3LOD、共有Geometry・共有material・InstancedMeshで実装する。`reference/okinawa-coral-viewer/` は同じTerrain、SkyDome、WaterPass、FieldRendererを使った70 m四方の浅海デモ。外周には海底の粗い背景メッシュを続け、透明な水中から正方形の端が露出しないようにする。背景は配置・地形判定の範囲を拡張しない。既存の漫湖・東京湾にサンゴを追加せず、新しいサンゴ礁マップの `corals` 設定で有効化する。新しい魚・動く生物・建物は追加しない。

## 形状と個体差

各種の4形状は固定の生成seedから作る。群体seedは `scale`、`growthDirection`、`branchDensity`、`surfaceColor`、`damageAmount`、`algaeAmount`、向きを決める。枝密度は4形状の選択と小さな横幅差に対応し、群体ごとに重いGeometryを作らない。4形状を超える無制限の固有トポロジーを生成する機構ではない。群生のscaleは0.42–1.32で若い小群体と大群体を混ぜ、区画ごとに優占する形を変えた混生にする。

- 指状：枝数・高さ・分岐・欠損端・偏りが変わる。
- テーブル：低い付着部から不均等な斜め支持枝が広がる。冠部は主分岐と短い少数の融合枝、上向きの短い分枝を持ち、三角格子の繰り返しを抑える。支持高さ・広がり・主枝数・枝密度・微小枝の向きが変わる。
- 塊状：高さ・幅・融合した隆起・外周が変わる。
- 葉状：5–8枚の開いた扇状の葉状板、広がり・重なり・湾曲・波形が変わる。各板はずらした基部から連続して立ち上がり、中央に露出した円柱の支えを持たない。
- 脳状：幅・高さ・表面の蛇行壁が変わる。

指状群体のLOD0/1は、枝ごとに閉じたチューブを重ねず、同じ成長骨格から距離場で滑らかに融合した一体の表面を生成する。隣接セルで共通の分割と頂点を使い、枝の接合部に交差面や輪状の継ぎ目を残さない。表面模様はローカル座標で投影し、距離場から求めた遮蔽を間接光にだけ適用する。計算は共有形状の初回生成時だけで、毎フレームには行わない。LOD0は約33–41万、LOD1は約4.6–5.7万triangles。近景の1形状のGPU用バッファは約10–13 MBで、生成中には追加のCPU作業領域を使う。共有cacheと近景数の上限で、群体ごとの再生成を防ぐ。

枝先は丸い閉じた面と浅い軸個体孔を持つ。支持枝と基部で海底へ接続する。幅広い塊状群体は海底の傾きに沿わせ、成長方向の傾斜で基部が浮かないようにする。

LODを作るときの乱数消費を保ち、LOD1の残した枝がLOD0の同じ枝を指す。細い枝の除去や微細面の消失による通常のLODポップはある。フェードで二重描画する複雑な遷移は導入していない。

## 質感と水中光

LOD0/1はMeshPhysicalMaterialのPBR、種別に共有する微細な隔壁・個体孔・谷の表面テクスチャと微細bump、淡い成長端、露出骨格、基部の藻類、控えめな組織の散乱感を持つ。ポリプごとのObject3Dは作らない。日中の収縮した状態を主対象とし、触手の複雑なアニメーションはない。これは実測したSSSではなく、薄い縁に寄与させる低コストの散乱近似。

1024×1024の共有RGBA8データatlasを5枚だけ保持する（mipmap込み約26.7 MiB、CPU側にも同容量を保持）。RGに16-bitの高さ、Bに窪み、Aに色素を格納し、mipmapは高さを復号して平均してから再格納する。近接時の高さの段差を減らし、LODごとの別textureを増やさない。画像の転載ではなく、個体孔・隔壁・陰影・色素の手続き的な生成結果で、脳状の谷には焼き込んだ反応拡散の高さ場を用いる。別のkitが同じtextureを使用できるよう、この固定数のcacheはkitのdisposeでは破棄しない。初回のatlas・Geometry生成にはCPU時間を要し、読み込み時に実行する。

個体孔と微細な凹凸は群体scaleを補正して実寸を保ち、小群体の個体孔まで縮小しない。個体孔はpixel footprintで薄め、遠景の細かな模様のちらつきを抑える。LOD2はMeshStandardMaterialで個体孔bumpと組織散乱を簡略化する。遠景テーブルは密集枝の外周を保つ薄い閉じた冠部に置換する。遠景の指状群体は516–696 trianglesまで削減し、近景の約33–41万 trianglesから表示負荷を下げる。ポリプのdetailを大量Meshとして持たない。

葉状サンゴの急な折れ目は実寸のトライプラナー投影で表面を描き、UVが圧縮された箇所の筋状の伸びを避ける。指状・塊状にも同じ投影を使う。テーブルのLOD0は約21–25万、LOD1は約4.5–5.4万、LOD2は約1,100 triangles。

サンゴ材料には水面から届く日光のRGB減衰、既存WaterPassにはカメラまでの水の長さからRGB減衰を適用する。視線の減衰を材料で二重にかけない。赤が先に落ち、緑・青が残る。仮の係数は吸収 `[0.1,0.025,0.012] /m`、低い濁度0.025。沖縄の特定海域の実測光学係数ではない。岩盤はサンゴ礁だけ白っぽい石灰質・石灰藻・細かな孔に切り替え、既存の捨石護岸の模様を流用しない。

LOD0/1の集光模様は水面・海底と同じWaveSetと時計を使い、影の中を光らせないよう直射光だけに適用する。低いLODではこの計算を省く。硬底に干潟用の泥の黒化・青灰色化・砂紋を重ねず、不規則な灰ベージュの石灰質と局所的な石灰藻にする。

RGB吸収を有効にした水質では、既存の低解像度反射passを水中からの全反射にも使う。水面の反対側をクリップし、深度から反射先までの距離を復元して往復の水中減衰をかける。水面が視野に入らない下向きのカメラでは反射描画を省き、低・超軽量画質では無効。近接する水面反射の画素化はMSAAと解像度設定で抑えるが、波の凹凸は平面反射への摂動であり完全な屈折ray tracingではない。`render.mirrorCalls` / `mirrorTriangles` は本体の描画回数とは別に記録する。

## 組み込み

既存マップに任意で追加するJSONの例（サンゴが生える硬底と深さを地形側で用意する）：

```json
"corals": {
  "seed": 7123,
  "waterLevel": 0,
  "lowWater": -0.65,
  "minSpacing": 0.2,
  "clusters": [{"x": 0, "z": 0, "radius": 20, "count": 100, "exposure": 0.5}]
}
```

`World.create/update/dispose` と画質切替に統合済み。陸、泥、砂、水路、急斜面、陥没、低潮位で上端が干出する場所には配置しない。底質は `rock` / `gravel` のみを許可する。高さは地形と同じ基準。生物の自然スポーン設定とは独立した環境アセットなので、`animals: false` でもサンゴを表示できる。`lowWater` はマップ作者が実際の水位基準に合わせて設定する。

```ts
import { CoralKit, OkinawaCoral, coralSpec } from './src/world/coral';
const kit = new CoralKit();
const spec = coralSpec(7123, 0, 'acropora_digitifera');
spec.x = 2; spec.z = 4;
const colony = new OkinawaCoral(kit, spec, terrain);
scene.add(colony);
kit.light.water.value = tideLevel;
kit.light.sun.value.copy(sunDirection);
colony.setLod(0);
// 所有する群体をすべて解放してから共有kitを解放
colony.dispose(); kit.dispose();
```

群生はCoralReefで配置する。32 m区画×5種×4形状×3LODごとにInstancedMesh。sourceの頂点/index属性とmaterialsは共有し、matrix・色・損傷・藻類属性はbatchの所有。batchを捨てても別batchの共有GPUバッファを破壊しない。shared属性を登録した最初のviewはkit全体のdisposeまで保持し、数を最大60に制限する。

| 画質 | LOD0 | LOD1まで | 表示限界 | 近景LOD0最大数 |
|---|---:|---:|---:|---:|
| high | 3.5 m | 16 m | 85 m | 4 |
| mid | 2.6 m | 12 m | 65 m | 2 |
| low | 1.6 m | 9 m | 50 m | 1 |
| minimal | なし | 6 m | 35 m | 0 |

距離は群体scaleで調整し、切替にはhysteresisを持つ。低・超軽量画質とLOD2は群体の影を省く。画面外はInstancedMeshの実際の境界でカリングする。任意LOD固定はビューアの造形検査用。

## 検証・起動

- `npm run dev` → `reference/okinawa-coral-viewer/`。5種・単体・4形状・表面から10〜20 cmの近接・群生・LOD・画質・水中/中立表示を切り替えられる。
- `npm run render:okinawa-coral`。実Chromiumで全種・表面・各LOD・群生・水面の裏側を描画し、shaderエラーとWorld統合を検査する。20構図と、実際のWorldでサンゴ群体へ向けた統合画像・結果を `screenshots/` に保存する。
- `npm run check`、`npm run build`。種数、形状、seed、有限geometry、表裏normal、LOD削減、共有資源の寿命、低潮位の配置、旧マップの光学設定を検査する。

画質評価では、テーブルの直立小枝が柵状に見えること、葉状板の均質な厚み、指状群体の滑らかな輪郭、反復する表面模様、周囲の平坦な岩盤などに人工的な見え方が残る。葉状板を斜めから見る近接構図では、微細模様が筋状に見える箇所もある。現段階は実写相当のAAA完成版ではない。実写との照合と実機GPUでのFPS測定も未完了。ブラウザ検証のtriangle/draw数と実際の描画画像を示し、機能テストの合格を写実性の達成とは扱わない。

2026-10-12の検証では、型検査・414 tests（45 files）・データ検証・production buildが通過した。追加した反射検査は水面の上下のクリップ、深度復元、減衰経路、水質・画質のゲート、下向きカメラの描画省略を確認する。表面の検査はWaveSetを交換した後の同期、LOD2での計算省略、16-bit高さのmipmap精度を確認する。

全種の1K atlasと共有LODを初めて生成する新規サンゴ統合テストは、単独でも約8秒を要したため、その1件の制限を5秒から15秒へ変更した。assertionは維持し、描画処理を止めて `npm run test -- --maxWorkers=2` の全件再実行が通過した。既存amamo等のテストは変更していない。これは初回のCPU生成時間の参考であり、描画FPSではない。サンゴの再現性検査は20形状を個別に検査し、同一seedの頂点一致・有限値・LOD削減の確認を維持する。

その後のLOD予算調整と反射用textureの解放修正では、影響する46 tests・型検査・buildを再実行して通過した。反射無効時はsampler参照も外し、破棄した深度textureが再作成されることを防ぐ。

Chromiumによる20構図とWorld統合の描画検査後、最終調整が影響する群生3画質・水面反射の4構図とWorld統合も再撮影した。ページ・shaderエラーは検出されなかった。同じ296群体の群生構図で記録した描画負荷は以下のとおり。SwiftShaderでの検証値であり、実機GPUのFPSや快適さを保証する数値ではない。

|---|---:|---:|---:|---:|
| high | 91 | 4,782,167 | 32 | 882,617 |
| low | 59 | 1,086,914 | 0 | 0 |
