# UI の設計と自己レビュー（6 回目）

目標: Awwwards / Webby / FWA で評価される水準の画面構成。評価は毎回スクリーンショット（1440×900 と 390×844）を撮り、下のチェックリストで採点し、落ちた項目を直して撮り直す。

## 設計方針（デザインシステム）

- 概念: 「観察の記録帳」。暗く静かな地の上に、水槽と干潟だけが明るい。UI は語らず、数字と余白で語る。
- 書体: 見出し・ワードマークは Shippori Mincho B1（明朝、編集物の気配）、UI 本文は Zen Kaku Gothic New（幾何学的で読みやすい）、数字はすべて DM Mono（等幅、桁が揃う）。Google Fonts から読み込み、無ければ Hiragino / Noto に落ちる。
- 色: 墨色 3 段（#050b0e / #0a1317 / #0f1c21）、文字 2 段と薄文字 2 段、アクセントは潮の青緑 1 色（#7fe3d2）、暖色の砂（#e8cf9a）は満干の区別と月だけに使う。線は白 10% と 18% の髪線。
- 面: ガラス面は 1 種類（黒 50% + blur 16px + 髪線）。角丸は 8 / 14 / 22 の 3 段。影は 1 種類。
- 間隔: 4 の倍数。カード内は 26/30、HUD は画面端から 20/24。
- 動き: 画面は fade 0.3 s、要素は rise 0.55 s（14px 上昇）を 80 ms ずつ遅らせて現れる。ホバーは 0.25 s、同じイージング（0.2, 0.8, 0.2, 1）。`prefers-reduced-motion` で止まる。
- 記号: 絵文字を使わない。月はその日の欠け方を描いた SVG、キーはキーキャップ、矢印・閉じるは線画。
- 文言: 見出しは短く、補足は eyebrow（小さな字間広めの見出し）に。数字には必ず単位を薄く添える。

## チェックリスト（各 0〜2 点、合計 24 点中 21 点以上で合格）

1. 第一印象: 画面を 1 秒見て主役（水槽／干潟）が分かるか。UI が主役を邪魔していないか。
2. 階層: 一番大きい文字が一番大事な情報か（ホーム: 時刻と潮位。タイトル: 名前）。
3. 書体: 3 書体の役割が守られているか。日本語とラテン・数字の大きさが揃って見えるか。
4. 余白とリズム: 間隔が 4 の倍数で、要素の間隔が内側の余白より広いか。
5. 整列: 端が揃っているか（左上・右上・下中央の 3 群）。
6. 色: アクセントが 1 か所に効いているか。暖色は意味（満潮／干潮・月）だけに使われているか。
7. コントラスト: 本文 4.5:1、薄文字 3:1 以上。ガラス越しでも読めるか。
8. 動き: 入場が自然で、同時に動きすぎないか。ホバーに応答があるか。
9. 一貫性: 閉じるボタン・キーキャップ・eyebrow・カード頭が全画面で同じか。
10. 細部: 絵文字・ずれ・折り返し・切れがないか。
11. 携帯幅: 390px で崩れず、主要操作に届くか。
12. 没入: ゲーム画面の HUD が邪魔をせず、必要なときに読めるか。
