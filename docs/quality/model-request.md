# モデル制作の依頼の手引き

生きもののモデルを作ってもらうとき（人に頼むときも、Claude のセッションに頼むときも）、依頼の文に入れること、作る人に先に読んでもらうことをまとめたもの。最後の §10 に依頼書のひな形がある。

- 数値の正本は `tools/models/budget.json`。理由と各種の現状は [容量予算](model-budget.md)。形式の細部は [3D モデル仕様](../spec/03_creature_ai_and_models.md) の §7。
- この文書とコード・`budget.json` が食い違ったら、コードと `budget.json` が正しい。この文書を直す。

## 1. 依頼の前に決めること

| 項目 | 決め方 | 例 |
|---|---|---|
| 種と形態 | 種データ（`public/data/species/<学名>.json`）の種。成長段階（`stages`）、雌雄、婚姻色、抱卵など、形が変わる形態ごとに 1 組 | マハゼは幼魚・若魚・成魚の 3 組。エドハゼは＋抱卵、ヒメハゼは＋婚姻色の雄 |
| 大きさの区分 | 種データの最大の長さ（全長・甲幅・殻長: `size.length_mm.max`）で S（〜35 mm）・M（〜120 mm）・L（〜300 mm）・XL（それ以上） | 200 mm まで育つマハゼは L。区分で §4 の上限が決まる |
| 作り方 | GLB（ビルダーが書き出すファイル）か、手続き生成（ドライバが実行時に組み立てる）か（§2） | ハゼ 3 種は GLB。ほかの多くは手続き生成 |
| 出る場所と数 | 地図、水中か陸か、1 か所に何体出るか（群れ・巣穴の密度） | コメツキガニは最大 44 匹。ハクは 1 群れ 20〜30 尾 |
| 透けるところ | 部位と方式（§6）。透けないなら「不透明」と書く | ハゼの胴体は全段階で透ける。ハクは薄い部位だけ |
| 砂との関わり | 砂煙を立てるか、潜るか、底に寝るか（§7） | アカエイ・イシガレイ・ミミイカは砂煙を立てる |
| 動き | 必要なクリップ（§3）と、手続きで動かす関節 | `Idle`・`Move` は必須。あくび・潜砂などは種ごと |

## 2. 納品の形

### 共通

- 単位はメートル。+Y が上、+Z が前（頭の向き）、+X が生きものの左。
- 原点は「体の中心の真下の接地面」。歩く動物は脚の接地面、魚は腹の最下点、鳥は足の接地面。合わせられないときはルートの extras に `contactY` を入れる（マハゼ）。
- ルートノード名は `<種の ID>_<形態>`。extras に `higata` を持つ:

  ```json
  { "species": "acanthogobius_flavimanus", "stage": "juvenile", "totalLength_mm": 50.5,
    "forward": "+Z", "up": "+Y", "contactY_m": -0.0034,
    "rig": { "axes": {} }, "clips": { "moveSpeed_mps": 0.25 } }
  ```

- **1 形態につき 3 段階**（hero・lod1・lod2）。hero を 1 つだけ作って 3 段階に使い回すのは不可。シロチドリは今そうなっていて、遠景も 9.1 万三角形・関節 232 で予算を大きく超え、10 m より先は仮のモデルに切り替えている。
- 参考写真は形・模様・色の照合にだけ使う。権利の分からない写真は、モデルにもリポジトリにも入れない（測った比率や色の値だけを残す）。
- 種ごとの説明を `docs/models/<種>/README.md` に書く: 調べたこと（部位ごとの特徴とモデルでの作り）、写真との照合、描画の段階の表（距離・三角形・内容）、確かめ方。各段階の静止画（`lod0.jpg`・`lod1.jpg`・`lod2.jpg` など）を同じ向き・同じ光で並べる。

### GLB で納める場合

- glTF 2.0 バイナリ。Khronos glTF Validator でエラー 0。使ってよい拡張は `KHR_mesh_quantization`・`KHR_materials_ior`・`KHR_materials_clearcoat`。`KHR_materials_transmission`・`volume` は入れない（§6。入れても lod1・lod2 では読み込むときに切られる: `src/creatures/models/ModelLoader.ts` の `prepareMaterial`）。
- ファイルは `<名前>.hero.glb`・`<名前>.lod1.glb`・`<名前>.lod2.glb`。元を `src/assets/models/<種>/` に置き、`npm run models:pack` でゲームが読む圧縮版（`src/assets/models-packed/`）を作る。両方をコミットする。
- 作り直せるように、ビルダー `tools/models/<種>/build.mjs --tier hero|lod1|lod2` で書き出すのが基本（形もテクスチャもスクリプトから作る。ハゼ 3 種は組み立てを `tools/lib/gobyBuild.mjs` で共有）。外の道具で作った GLB を入れるときも、3 段階・名前・extras・予算は同じ。
- 種データの `model` に 3 段階のファイル（形態ごとは `stages[].model`）、`modelLength_mm`（モデルの全長）、`driver`、`clips` を書く。

### 手続き生成で納める場合

- コードは `src/creatures/species/<種>/`（形・マテリアル・姿勢・行動・ドライバ）。`src/creatures/drivers/index.ts` の `DRIVERS` に登録する:

  | 項目 | 役目 |
  |---|---|
  | `create` | ドライバ |
  | `placeholder` | 干潟で使うモデル（段階を自分で持つ） |
  | `preview` | 図鑑とタモ網の中で見せる 1 体 |
  | `keep` | 全段階のシェーダーを読み込み中に用意しておくための、描かないモデル（§5 の 9） |
  | `body` | 体つき（ぶつかり合い・接地の形。§7） |
  | `nearDistance` | この距離までを「近い」とみなす（毎フレーム更新） |

- 段階ごとの形を 1 つだけ作って全個体で共有し、個体は自分の骨格だけを持つ（ハク・ヨウジウオの作り。段階の切り替えは `THREE.LOD`）。
- 三角形・描画の回数・関節・実行時に作るテクスチャを数えて、[容量予算](model-budget.md) の §5 の表に書く。

## 3. リグとクリップ

- ルート関節は `J_root`。体軸は `J_sp1` … の連番、頭は `J_head`、左右は `_L` / `_R`。静止姿勢は全関節が単位回転。手続きで回す軸は extras の `higata.rig.axes` に入れる。
- **3 段階で関節名・クリップ名・モーフ名をそろえる。** lod2 は関節を減らしてよいが、残す関節の名前は同じにし、消した関節の重みは親に移す（ハゼの lod2: 頭の細かな関節は頭へ、胸びれと眼は親へ。24 → 12 関節）。
- 関節の上限（`budget.json` の `joints`）:

  | 段階 | S | M | L | XL |
  |---|---|---|---|---|
  | lod2 | 4 | 12 | 16 | 24 |
  | lod1 | 16 | 32 | 48 | 64 |
  | hero | 64 | 96 | 128 | 128 |

- クリップ:

  | 名前 | 必須か | 内容 |
  |---|---|---|
  | `Idle` | 必須 | ループ。呼吸や小さな動き |
  | `Move` | 必須 | ループ。1 周期の歩き・泳ぎ。移動の速さとの対応を extras の `higata.clips.moveSpeed_mps` に |
  | `Flee` | 任意 | 速い移動 |
  | `Fly` | 鳥は必須 | 羽ばたき 1 回 |
  | 種ごと | 任意 | `Yawn`・`Burrow`・`Peck` など。図鑑の行動 ID に対応させる |

- 手続きで姿勢を作る種（ハゼの `pose.js`、ヨウジウオの `pose.ts`）は、クリップの代わりにドライバが関節を毎フレーム書く。ひれの「畳む・水でしなる・波打つ」はモーフで持てる（マハゼ）。

## 4. 予算

### 4.1 段階の使われ方

| 段階 | 使われ方 | 画面上の大きさ（1080p） | 同時に出る数 |
|---|---|---|---|
| lod2（遠景） | 近くの数体以外のすべて。描画距離（種データの `viewDistance_m`。なければ平均の体長 × 400 で、水中 14 m・陸 40 m・鳥 120 m まで）まで。**画質「超軽量」では観察・水槽・観察ケースでも lod2** | 10 cm の魚が 2 m で約 50 px、10 m で約 10 px | 1 種で数十体。地図全体で 100〜300 体 |
| lod1（近景） | 10 m 以内で近い順に、画質ごとの数（超軽量 0、低 2、中 4、高 6、最高 8 体） | しゃがんで 0.5 m で 10 cm の魚が約 200 px | 最大 8 体 |
| hero（観察・水槽） | 観察している 1 体と、水槽（中以上） | 画面いっぱい（約 1000 px） | 観察 1 体＋水槽の種類数 |

### 4.2 1 ファイル（1 種・1 形態・1 段階）の上限

| 段階 | S（〜35 mm） | M（〜120 mm） | L（〜300 mm） | XL（それ以上） |
|---|---|---|---|---|
| lod2 | 300 / 1・128 / 0.05 MB / 0.1 MB / 1 | 1,500 / 2・256 / 0.3 MB / 0.5 MB / 2 | 3,000 / 3・512 / 0.8 MB / 1.5 MB / 2 | 4,000 / 3・512 / 1 MB / 1.5 MB / 3 |
| lod1 | 3,000 / 3・256 / 0.3 MB / 0.5 MB / 2 | 15,000 / 4・1024 / 4 MB / 6 MB / 4 | 25,000 / 4・1024 / 4 MB / 6 MB / 4 | 30,000 / 4・2048 / 12 MB / 22 MB / 4 |
| hero | 10 万 / 6・1024 / 8 MB / 12 MB / 4 | 15 万 / 8・2048 / 20 MB / 40 MB / 6 | 25 万 / 8・2048 / 25 MB / 48 MB / 6 | 30 万 / 8・2048 / 25 MB / 48 MB / 6 |

### 4.3 全体の上限（ほかの種と分け合う）

- 地図 1 つに出る全種の lod2 の合計: ダウンロード 8 MB・GPU 16 MB（今は東なぎさで 7.7 MB を使っていて、残りは少ない）。
- 1 フレームの生きもの全体: 画質「高」で 40 万三角形・描画 250 回、「低」で 15 万三角形・120 回。
- 予算を超えるときは、依頼の段階で理由と、代わりに何を減らすかを書く。

### 4.4 テクスチャの重さの目安

ゲームでは KTX2（UASTC）に変換され、GPU では 1 画素 1 バイト（ミップマップ込みで 4/3 倍）になる。

| 一辺 | GPU | ダウンロード |
|---|---|---|
| 2048 | 5.6 MB | 約 3.6 MB |
| 1024 | 1.4 MB | 約 0.9 MB |
| 512 | 0.35 MB | 約 0.22 MB |
| 256 | 0.09 MB | 約 0.06 MB |

## 5. LOD と軽量化の決まり

1. **段階ごとに本当に軽くする。** 細かさは画面に占める大きさで決める。lod2 は画面で 10〜50 px にしかならないので、その大きさで見分けられない形（口の中、鰭条の 1 本ずつ、鱗）は作らない（コメツキガニは前、20 px にしか見えないカニに 27,000 三角形を描いていた）。遠くでまとめて 1 回の描画にしても、三角形が減らなければ軽くなっていない（ケフサイソガニ・ミズヒキゴカイは今、遠景でも三角形が減らない）。ただし、種の見分けになる輪郭は全段階に残す（ガザミは甲の歯・棘・はさみ・遊泳脚を lod2 まで残す）。
2. **段階ごとに省くもの**（ハゼの例）:

   | 段階 | 持つもの | 省くもの |
   |---|---|---|
   | hero | 口と鰓の内部（開く口・鰓蓋）、眼の屈折、ひれの法線、吻端の専用テクスチャ。テクスチャ 8 枚 | — |
   | lod1 | 胴体・ひれ・眼。テクスチャ 4 枚 | 口と鰓の内部、吻端の専用テクスチャ |
   | lod2 | 胴体と、ひれと眼をまとめた 1 つのメッシュ（alphaTest。ひれは休む姿勢で固定）。テクスチャ 3 枚、マテリアル 2、関節 12 | 法線マップ、ひれの動き、頭の細かな関節 |

   手続き生成のハクは lod2 で体と尾を 1 つのメッシュにして、不透明・1 回の描画・192 三角形にしている。
3. **テクスチャは段階ごとに縮め、チャンネルにまとめる。** lod2 は 128〜512、lod1 は 256〜1024。全段階で同じ 2048 を持たない。模様の層（色素の層、婚姻色、模様の種類）は枚数を増やさず、1 枚のチャンネルや頂点色にまとめる。例（ハゼの胴体）:
   - ベースカラー: RGB に地色、A に黄色素胞
   - 法線: RG に法線の X・Y、B に遮蔽（AO）、A に粗さ
   - 色素: RGB に模様 1〜3 の黒色素胞、A に虹色素胞
   - ひれのアトラス: 色と被覆率、空いた隅に虹彩

   マハゼの模様 3 種 × 色 3 種の 9 通りは、このチャンネルと、GLB に入れた色の表（シェーダーの値）で作る。テクスチャを 9 組持たない。
4. **段階どうしでマテリアルの機能をそろえる。** マップの有無、透過、alphaTest を段階ごとに変えると、そのたびに別のシェーダーができて読み込みが延びる。変えてよいのは lod2 の不透明化だけ。1 種のシェーダーの組み合わせは 2 つまで。
5. **個体ごとに作り直さない。** 形とマテリアルは種・形態ごとに共有し、個体差は近景ではユニフォーム、遠景では頂点色の掛け算で出す。S 区分と二枚貝・巻貝は、遠景を InstancedMesh で 1 種 1 回の描画にする。悪い例: エビは遠景で個体ごとに形を作り直していて、遠景がいちばん重い（2.9 万三角形・描画 45 回）。ヤドカリは発生のたびに観察用の蟹を 1 体作って捨てている。
6. **描画の回数はマテリアルの数。** 同じマテリアルのメッシュは 1 つにまとめる。遠景は 1〜2 回で描けるように作る。
7. **画質の設定に従う。** 手続き生成の種も、段階を距離だけで決めない。

   | 画質 | 近景の数 `lod1Count` | 使える段階 `modelTier` | 観察用の材質 `hero` | 数 `creatureScale` | 描画距離 `viewScale` | 接地影 | 砂煙 |
   |---|---|---|---|---|---|---|---|
   | 超軽量 | 0 | lod2 だけ | なし | 0.35 | 0.6 | なし | 0 |
   | 低 | 2 | lod1 まで | あり | 0.6 | 0.85 | あり | 0.5 |
   | 中 | 4 | hero まで | あり | 1 | 1 | あり | 1 |
   | 高 | 6 | hero まで | あり | 1 | 1 | あり | 1 |
   | 最高（PC の干潟だけ） | 8 | hero まで | あり | 1 | 1 | あり | 1 |

   値は `src/core/Settings.ts` の `QUALITY_PRESETS`。超軽量の図鑑は 3D を描かず、モデルを撮った 640×400 の静止画を出す（新しい種を入れたら `tools/photos/capture.mjs` で撮り直す）。
8. **影。** lod2 は影を落とさない（`ModelLoader` が切る）。太陽の影の地図は 1 画素が数 cm で、小さな魚には粗すぎる。小さな魚は影を落とさず、底に魚の形のぼかした「接地影」を置く（ハクの `ContactShadows` を共用。1 グループ 1 回の描画の InstancedMesh。超軽量では出さない）。
9. **シェーダーを先に用意する。** three はマテリアルがなくなるとそのシェーダーを捨てるので、種が画面から消えて戻るたびに、その場でコンパイルし直して止まる。全段階のマテリアルを持つ描かないモデルを `keep` で返す（読み込み画面でコンパイルされる。`tests/unit/keptShaders.test.ts`）。砂煙を使う種は `keepSandDust(parent)` も足す。
10. **毎フレーム物を作らない。** ドライバの `update` の中でジオメトリ・マテリアル・ベクトルを新しく作らない。
11. **細かいものは遠くで消す。** TAA（ちらつきを抑える）は PC の中以上だけで、スマホと低・超軽量にはない。細い縞・継ぎ目・点の模様は、遠くでは平均の色に置き換える（ヨウジウオは遠くで骨板の継ぎ目と黒点を消す。エビの縞は画素ごとに描いて `fwidth` でぼかす）。速いひれの動きもちらつくので、見せる周波数を抑えて振幅とぼかしで表す（ヨウジウオの背びれは実物の 13〜26 Hz を 12.5 Hz で止める）。スマホでも同じモデルが動く（テクスチャは ASTC か ETC2 になる）。
12. **圧縮で壊さない。** `npm run models:pack` はテクスチャを KTX2（UASTC＋Zstandard）、形を meshopt にする。ノーマルマップは normal-map の設定、色は sRGB、それ以外（粗さ・遮蔽・模様の分布）は線形で圧縮するので、テクスチャの役目を取り違えない。圧縮後に PSNR が 30 dB を下回ると失敗する。glTF の中身は番号ごとそのまま残す（ハゼの extras はテクスチャを番号で指している。gltf-transform などで組み直すと番号がずれる）。

## 6. 透過・半透明

### 6.1 原則

- **three の transmission（`KHR_materials_transmission`、`MeshPhysicalMaterial.transmission`）は使わない。** これがあるだけで、three は毎フレーム、シーン全体をもう 1 回描く。生きものは同じ種が何十体も出るので、なおさら使えない。水槽のガラス蓋とヒーターもこれを使っていたのでやめた（[水槽の描画](../models/aquarium/water.md)。ヒーロー魚の描き方の見直しと合わせて、1 フレームが 5,854 → 3,050 ms）。GLB の lod1・lod2 では読み込み時に切られる。
- 不透明で描けるものは不透明で描き、「透けて見える」ことはシェーダーで背後の光を足して表す（深度を書けるので、描く順の破綻が起きない）。
- 全体の不透明度を一律に下げない。薄いところ（尾柄・ひれ・吻）は透け、厚いところ（頭・腹）は濁り、黒い色素斑・背骨・内臓は光を通さない。
- 段階: 半透明の部位は hero と lod1 で半透明、lod2 では不透明にするか alphaTest（被覆率をアルファに入れる）。マテリアルの機能をそろえる決まり（§5 の 4）の例外はこれだけ。ハゼの胴体はさらに例外で、全段階で透ける。
- 水中ではつやを弱める。体表の粘液や角膜の屈折率は水に近いので、空気中の値（F0 0.028）のままだと白い鏡面光が乗って灰色に見える（ヒメハゼで実際に起きた。水中では約 0.0002）。強く光らせてよいのは虹色素胞の反射だけ。
- 混ぜて描く部位には、描く順（`renderOrder`）を決めておく。例: アミメハギは体 0 → 角膜 1 → ひれ 2。エビは鰓 1 → 筋肉と組織 2 → 殻 3。
- 潜ったら不透明に戻す。砂をかぶった半透明のひれは、砂の上にベールのように浮いて見える（イシガレイは潜っている間だけ、ひれを不透明の alphaTest にして深度を書く）。
- 細い切り抜きは遠くで消える。alphaTest の糸や毛は、ミップで平均されると閾値を下回って消える（タモ網は網袋をアルファブレンドにした）。alphaTest を使うなら alpha-to-coverage を付ける（ヤドカリの剛毛）。

### 6.2 方式（依頼にはどれを使うかを書く）

| 方式 | 重さ | 使っている種・部位 | 中身 |
|---|---|---|---|
| A. 不透明＋薄い所に背後の光を足す | 軽い（不透明と同じ 1 パス、深度を書く） | ハク（尾柄・背・唇）、ヨウジウオ（吻・尾の先・腹）、アミメハギ（皮膚の厚みで）、イシガレイ（縁・ひれの付け根・無眼側）、ガザミ（遊泳脚・膜・眼柄・稚ガニの甲）、アカエイ（逆光の縁の橙）、コメツキガニ（逆光の琥珀色） | 標準マテリアルを `onBeforeCompile` で拡張し、魚の向こうから来る水中の光と逆光を、薄さに応じて自発光として足す。ヨウジウオは腹壁の内側へ短く 4 歩たどって、腸・肝臓・鰾を皮膚の下の影として見せる |
| B. 深度を書かない半透明の膜 | 中（描く順に注意） | ひれ（ハク・ヨウジウオ・アミメハギ・イシガレイ・ミミイカ。ハゼの hero と lod1 は glTF の `BLEND`） | `transparent`・`depthWrite: false`・両面で、体のあと（`renderOrder` 2）に描く |
| C. 混ぜるが深度は書く | 中 | ミミイカの皮膚、アラムシロの軟体（足の縁）、ハゼの胴体（F） | 体そのものが薄く透ける。ミミイカは見る角度で縁が乳白になり、ハイライトの下ではアルファを上げて鏡面を暗くしない |
| D. ガラス（反射だけ） | 中 | アミメハギ・ミミイカの角膜、エビの殻 | premultiplied alpha、深度を書かない、フレネルの反射だけ。エビの殻は正面で澄み縁ほど濃く、その下の筋肉と組織も深度を書かない半透明、内臓は不透明（殻越しに見える） |
| E. alphaTest の切り抜き | 軽い（不透明として描ける） | ハゼの lod2 のひれと眼、ガザミとヤドカリの剛毛、潜ったイシガレイのひれ | 被覆率をアルファに入れ、閾値で切る |
| F. ハゼの胴体の透け | 中（1 画素で 9〜18 歩の追跡） | マハゼ・エドハゼ・ヒメハゼの胴体、全段階 | 深度を書く。GLB に入れた体の断面の表（512 断面）で、視線を皮膚で屈折させて体の反対側まで追い（近景 12＋6 歩、lod2 は 6＋3 歩）、組織・内臓・背骨・色素胞で減った分だけ背景を透かす。逆光では薄い部位が飴色に光る（`src/creatures/species/mahaze/bodyTranslucency.ts`） |
| G. 観察用の体積シェーダー | 重い（観察中の 1 匹だけ） | ハゼの観察（干潟は低以上、水槽は中以上で 1 匹） | 背景を先に描いたバッファ（`uBg`）を読み、体積をレイマーチ。ひれは 1 枚ごとに「透過率の掛け算」と「散乱光の足し算」の 2 パスで、毎フレーム奥から手前へ並べる |

- 迷ったら A から始める。透けて見えるのは「向こうの光が薄い所を通ってくる」ことなので、多くの部位は不透明のまま A で足りる。B〜D は、本当に向こうの物（砂、ほかのひれ、内臓）が見えなければならない部位だけにする。
- F・G を使う種は、GLB に体のデータを持たせる: 断面の表、脊椎の配置、内臓（楕円体と管）、組織の散乱と吸収、色素テクスチャのチャンネルの割り当て（マテリアルの `extras.mahaze`）。エドハゼは解剖のデータを GLB に、ヒメハゼは生成ツールの値を使う（[マハゼモデルの説明](../models/mahaze_juvenile_README.md) の「ゲームの中の透け」）。F は 3 種のハゼのための作りで、ほかの種に広げるなら依頼に「F を使う」と明記し、体のデータの作り方まで頼む。
- ハゼの胴体とひれの描く順: それぞれの中心の奥行きで並べる。そのため、メッシュごとのバウンディングスフィアを部位の中心に置く（`MahazeDriver`）。奥のひれは胴体越しに透け、手前のひれは胴体の上に描かれる。

### 6.3 依頼に書くこと

- どの部位が、どの段階で、どの方式で透けるか。
- 順光と逆光で何が見えるべきか（例: 逆光で背骨が体の中ほどの暗い線、内臓が胸びれの後ろの影。黒い斑は逆光でも黒）。
- 確かめ方: ハゼは `node tests/smoke/goby-translucency.mjs [--quality low|mid|high]`（3 種を並べ、観察カメラから順光と逆光で撮る）と `tests/unit/gobyTranslucency.test.ts`。新しい種も、順光・逆光の静止画を README に並べる。

## 7. 砂煙・潜砂・接地

### 7.1 砂煙

全種で共有する 1 つの層で描く（`src/creatures/fx/SandDust.ts`、説明は [砂煙](../creatures/sand-dust.md)）。生きもののいるグループごとに 1 回の描画（点スプライト、最大 2048 粒）。今はアカエイ・イシガレイ・ミミイカが使う。

- 舞うもの: 泥の雲（ゆっくり沈む）、砂粒（1 秒ほどで落ちる）、墨（ミミイカ。ほとんど沈まない）。足元の底質で量と残り方が変わる（泥の上は雲が多く長く、砂の上は粒が多く雲はすぐ沈む）。
- 依頼に書くこと:
  - **出る場面**: 離底・着底・潜砂・逃避・採餌・底すれすれの遊泳など。
  - **出る位置**: 体盤の縁、体の下、口、鰓孔、尾の後ろ、漏斗など。ドライバが体の部位（関節や輪郭の点）から位置を引けるように作っておく。
  - **潜った姿**: 潜砂のクリップや姿勢、背に砂がかかる・積もった砂が滑り落ちる見せ方（イシガレイ・アカエイ）。潜っている間は物理の `away`（ぶつかり合わない）。
- 出さないとき: 砂のない場所（観察ケース、底砂のない水槽）、遠い個体（アカエイ 22 m まで、イシガレイ 3 m まで、ミミイカは lod2 で出さない）、画質（超軽量 0、低 0.5、中以上 1）。
- 付け方のコードは [砂煙](../creatures/sand-dust.md) の §6。`keep` に `keepSandDust(parent)` を足す。
- 確かめ方: `tests/unit/sandDust.test.ts`、種ごとの場面の静止画（`npm run render:sand-dust` の撮り方）。

### 7.2 接地とぶつかり合い

共通の物理の層（`src/creatures/physics/`、説明は [生きものの物理](../creatures/physics.md)）が受け持つ。モデルの側で用意すること:

- **体つき**（`DRIVERS[...].body`、全長に対する割合）: 幅 `width`、高さ `height`、尾を除いた芯の長さ `core`、芯の中心が原点からどれだけ前か `ahead`。体はこれで作るカプセル（丸い種は円盤）として押し分けられる。
- **接地点**: 体の足跡の前・後・左・右の 4 点から、体を乗せる面の傾きを出す。底に寝る魚は接地点を決めておく（ハゼは吸盤の縁・腹・尾びれの下葉。それぞれを真下の地面に下ろす）。
- **脚で歩く種**: 押されたときに地面に置いた足も一緒にずらすので、足の位置をドライバが持てる作りにする（エビ・ヤドカリ・アカエイの尾）。
- **小さな遊泳種**: うねりと寄せ波で前後に運ばれ、背が最大約 17° 振れる（3 cm の稚魚はほぼ水と一緒に、20 cm の魚はほとんど運ばれない）。モデルは姿勢に傾きを足せればよい。
- 確かめ方: `node tests/smoke/physics.mjs`（重ねて置いて数秒で離れるか、斜面に沿って寝るか）、`tests/unit/creaturePhysics.test.ts`。
