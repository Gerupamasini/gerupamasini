# 生きものモデルの容量予算（基本方針）

生きもの 1 種・LOD 1 段ごとに、ゲームが成り立つ上限を決める。新しく作るモデル、作り直すモデルはこの中に収める。数値の正本は `tools/models/budget.json`。GLB のモデルは `npm run models:budget` で照合できる（超過を報告するだけ。`--strict` で失敗にする）。手続き生成の種は §5 の表に記録し、作り直したら更新する。

## 1. なぜこの数値か（ゲーム側の条件）

| 段階 | 使われ方 | 画面上の大きさ（1080p） | 同時に出る数 |
|---|---|---|---|
| lod2（遠景） | 近くの数体以外のすべて。描画距離（水中 14 m、陸 40 m、鳥 120 m）まで | 10 cm の魚が 2 m で約 50 px、10 m で約 10 px | 1 種で数十体。マップ全体で 100〜300 体 |
| lod1（近景） | 10 m 以内で近い順に、画質ごとの数（超軽量 0、低 2、中 4、高 6、最高 8 体） | しゃがんで 0.5 m で 10 cm の魚が約 200 px | 最大 8 体 |
| hero（観察・水槽） | 観察している 1 体と、水槽（中・高のとき。最大 20 体） | 画面いっぱい（約 1000 px） | 観察 1 体＋水槽の種類数 |

これを実際の機械に当てはめた全体の上限:

- **ダウンロード**: Web 版で干潟に入るとき、生きもののモデル（その地図に出る全種の lod2）は **8 MB まで**。今は 東なぎさ 7.7 MB、走水 1.0 MB（2026-10-14 にハゼ 3 種の遠景を軽くするまでは 47.6 MB と 29.1 MB で、20 Mbps の回線ではこれだけで 20 秒ほどかかっていた）。
- **GPU メモリ**: 地図 1 つの lod2 の合計は **16 MB まで**。lod1 は同時に 8 体分で 48 MB まで、hero は 1 体 48 MB まで。内蔵 GPU（共有 1.5〜2 GB）でも、ゲーム全体が 1 GB に収まる配分。
- **1 フレームの生きもの**: 高で **40 万三角形・250 回の描画まで**、低で 15 万三角形・120 回まで。地形・水・植物が残りを使う。

テクスチャの容量の目安（KTX2 UASTC。GPU では BC7 / ASTC になり 1 画素 1 バイト、ミップマップ込みで 4/3 倍。ダウンロードは Zstd で 1 画素 0.6 バイトほど）:

| 一辺 | GPU | ダウンロード |
|---|---|---|
| 2048 | 5.6 MB | 約 3.6 MB |
| 1024 | 1.4 MB | 約 0.9 MB |
| 512 | 0.35 MB | 約 0.22 MB |
| 256 | 0.09 MB | 約 0.06 MB |

|---|---|---|---|---|
| lod2 | 300 / 1 枚・128 / 0.05 MB / 0.1 MB / 1 / 4 | 1,500 / 2 枚・256 / 0.3 MB / 0.5 MB / 2 / 12 | 3,000 / 3 枚・512 / 0.8 MB / 1.5 MB / 2 / 16 | 4,000 / 3 枚・512 / 1 MB / 1.5 MB / 3 / 24 |
| lod1 | 3,000 / 3 枚・256 / 0.3 MB / 0.5 MB / 2 / 16 | 15,000 / 4 枚・1024 / 4 MB / 6 MB / 4 / 32 | 25,000 / 4 枚・1024 / 4 MB / 6 MB / 4 / 48 | 30,000 / 4 枚・2048 / 12 MB / 22 MB / 4 / 64 |

手続き生成の種も同じ表に従う（三角形・描画の回数・関節・実行時に作るテクスチャ）。マガキの礁の地図（全個体で共有するアトラス）のように、全個体で 1 つだけ持つものは種全体で数える。

## 4. 守ること

1. **段階ごとに本当に軽くする。** 遠景（lod2）は、その距離での画面上の大きさ（§1）に見合うだけにする。遠くでまとめて 1 回の描画にしても三角形が減っていなければ軽くなっていない。
2. **テクスチャは段階ごとに縮める。** lod2 は 128〜512、lod1 は 256〜1024。全段階で同じ 2048 を持たない。模様の層（色素の層、婚姻色など）は 1 枚のチャンネルや頂点色にまとめ、枚数を増やさない。
3. **段階どうしでマテリアルの機能をそろえる。** マップの有無、透過、alphaTest を段階ごとに変えると、そのたびに別のシェーダーができて読み込みが延びる。変えてよいのは lod2 の不透明化だけ。1 種のシェーダーの組み合わせは 2 つまで。
4. **個体ごとに作り直さない。** 形（ジオメトリ）とマテリアルは種・形態ごとに共有し、個体差はユニフォームや頂点色で出す。S 区分と二枚貝・巻貝は、遠景を InstancedMesh で 1 種 1 回の描画にする。
5. **画質の設定に従う。** 近景の数（`lod1Count`）、観察用を使うか（`hero`、`modelTier`）、描画距離（`viewScale`）、数（`creatureScale`）。手続き生成の種も、自分の LOD を距離だけで決めず、これに従う。
6. **新しいモデルは、入れる前に `npm run models:budget` を通す**（手続き生成の種は三角形・描画の回数を数えて §5 に書く）。超えるときは理由と、代わりに減らすものを書く。

## 6. 直す順番

1. ~~マハゼ・エドハゼ・ヒメハゼの lod2 と lod1~~（2026-10-14 済み）: テクスチャを段階の大きさに縮め、色素の層をチャンネルにまとめた（模様と色はシェーダーの値で出す）。東なぎさの遠景が 47.6 MB から 7.7 MB に。観察用（hero）も同じ日に同じ作りで予算に入れた（下の 6）。組み立ては 3 種で共通の `tools/lib/gobyBuild.mjs`、マップの割り当ては `docs/models/mahaze_juvenile_README.md`。
2. シラタエビ・イソスジエビの遠景: 形を種で共有し、遠景を 1,500 三角形・1〜2 回の描画に。
3. コメツキガニの LOD1・LOD2: 5,600 と 1,400 を 3,000 と 300 に（遠景は InstancedMesh）。
4. シロチドリ: lod1・lod2 を作り、超軽量の仮モデルの切り替えを直す。
5. ヤドカリの発生時の作って捨てる処理、ケフサイソガニ・ガザミ・ミズヒキゴカイの遠景、材質の多い種（アサリ・ハマグリ・ミミイカ）。
6. ~~マハゼ・エドハゼ・ヒメハゼの観察用（hero）~~（2026-10-14 済み）: 三角形を予算まで減らし、テクスチャを 8 枚にまとめた（マハゼは 9 通りの組み合わせを遠近の段階と同じくチャンネルとシェーダーの値に。透過・厚みの 1 枚をやめ、AO と粗さを空いたチャンネルへ、虹彩をひれのアトラスの隅へ）。観察用の標準の材質と lod1 は同じシェーダーになる（§4 の 3）。
