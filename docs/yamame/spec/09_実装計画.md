# 09 実装計画(ヤマメ Oncorhynchus masou masou 河川型 超写実3Dモデル)

対象読者: 利用者(ゲーム開発者)と実装エージェント。本章は 02〜07 の仕様を、**実装フェーズ P0〜P7**に分け、各フェーズの成果物・受け入れ基準・規模・リスク、最初の縦切り(Vertical Slice)、利用者に確認したい決定事項を定める。数値の根拠は各章のタグを引く。新しい数値は [E] とする。

## 9.0 読み方と見積りの注意

- **見積り規模**: 資料に根拠が無いため、すべて [E] の**相対規模**。S=半日程度、M=1〜2 日、L=3〜5 日、XL=1 週間超(実装エージェントの作業量の目安)。実機計測やデータ提供の待ち時間は含めない。
- **受け入れ基準**: 数値(07 §7.7 の T-A*/AT-*/A-*)と、固定条件のスクリーンショット(07 §7.7.5。決定論的)で書く。**映像との比較による「泳ぎが自然か」は人の判断**で、自動化できない(参照映像は全て未視聴 [spec05 §5.9.1])。
- **スナップショットの標準条件** [E]: 1280×720、縦 FOV 50°、側面は直交カメラ(シルエット比較用)、斜め前・上は透視カメラ。SL=0.19 m の個体で、距離 0.5 m の透視なら画面上の体長は約 294 px(縦 FOV 50° で視野高 0.466 m → 720 px、算術)。同じ距離で鱗ピッチ 0.7 %SL(1.33 mm)は約 2 px になり、鱗の格子の見え方の確認条件になる [spec02 §2.6, spec01 §1.5]。
- 各フェーズは**独立にマージ可能**な単位で、前フェーズの受け入れ基準を満たしてから進む。

## 9.1 フェーズ一覧と依存

```
P0 環境・ツールチェーン確認
 └─ P1 形態 (シルエット+頭部+鰭) GLB ──────────────┐
     └─ P2 リグ+手続き遊泳 ─┬─ P3 マテリアル・模様 ┤
                           ├─ P4 眼・口・鰓       ├─→ P6 LOD/最適化 ─→ P7 個体差
                           └─ P5 行動 (L1〜L4) ───┘
 (並走) W: WebGPU/TSL スパイク (P3 以降いつでも)
```

| フェーズ | 規模 [E] | 前提 | 主なリスク |
|---|---|---|---|
| P0 | M | なし | ツールチェーンの再現性(ヘッドレス起動、KTX2 非公式ツール) |
| P1 | L | P0 | 断面(体幅)が資料無し。頭部の形状 |
| P2 | L | P1 | 線形ブレンドスキニングの崩れ。体波の定義が [E] |
| P3 | L | P1(P2 と並行可) | 色の絶対値が不確か。サンプラー予算。法線マップ |
| P4 | M | P2 | 顎・鰓蓋の角度が全て [E]。角膜の透過コスト |
| P5 | XL | P2 | 閾値が全て [E]。行動の見た目の説得力 |
| P6 | L | P2〜P5 | 実 GPU が未測定。遠景方式が未検証 |
| P7 | M | P1〜P4 | 指標間の相関が未算出 |
| W | M(並走) | P3 | 実 WebGPU アダプタが無い環境 |

**クリティカルパス**: P0 → P1 → P2 → P5 → P6。P3・P4 は P2 と並行できる。

| リスク | ① **全ての性能数値が SwiftShader のもの**。実機で予算が破れたら、(a) skinned 数の削減、(b) 中景用 36 ボーン版の作成、(c) 影の間引き(その場合は `updateMatrixWorld(true)`→`skeleton.update()` を毎フレーム手動 [aud-B §3-11])、(d) 後処理の削減 ② InstancedMesh+morph の画質(断面回転による位置ずれ、法線モーフ精度)は未検証 [aud-B §4] ③ 実機の `MAX_TEXTURE_IMAGE_UNITS` が 16 だとサンプラー予算が不足しうる [aud-D §3-15] ④ KTX2 の実機変換先と VRAM が未確認 [aud-C §4] |
